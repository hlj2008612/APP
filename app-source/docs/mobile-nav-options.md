# 手机端导航栏：待定方案

> 状态：**待用户拍板**。当前仓库里已实施的是「方案 A」（零视觉变化）。
> 主理人两次尝试弹出选择框都超时（用户不在 GUI 前），因此没有替用户决定。

## 现状（实测，390x844）

```
nav 374x54 left=8 top=20
链接 首页36x28 / 照片墙48x28 / 影院36x28 / 画报36x28，font-size 12px
可点击区已被 ::after 扩展到 44px 高（视觉零变化）
```

320x568 下同样是 28px 盒子 + 44px 命中区，且没有横向溢出。

## 三个方案

### A. 保持现状（已实施）

- 只保留 44px 隐形触控扩展，导航布局一点不动
- 桌面端逐像素一致（实测导航区域差异 **0 / 136800 px = 0.0%**）
- 缺点：手机上 12px 字号偏小，四项挤在一起
- 实施位置：`src/components/NavBar.vue` 的 `@media (max-width: 767px)` 块（`.nav-link::after` / `.logout-btn::after`）

### B. 汉堡菜单（源站做法）

- 手机只留一个 40x40 图标按钮，点开抽屉列全部导航项
- 源站实测：375/390/414 下 header 66 高、`left:16`，文字导航容器 `hidden md:flex`，只剩一个 40x40 按钮
- 视觉变化最大，最省空间
- 代价：需要新增抽屉组件、处理焦点陷阱与 Esc 关闭、aria-expanded；`.glass-nav` 的高度逻辑要重写

### C. 纯图标导航

- 一行四个图标（首页/照片墙/影院/画报），去掉文字
- 省一半横向空间，触控目标更容易做大
- 代价：需要给 NavBar 加图标（当前没有图标资源，`public/icons.svg` 只有站点图标集，需确认是否可复用）；失去文字标签后需要 aria-label

## 若要实施方案 B 或 C

直接告诉主理人（AI 助手）选哪个即可，会按 `docs/mobile-spec.md` 的约束改：
六个视口 × 五个路由 `hasHScroll === false`、桌面端 >=1024px 逐像素不变、不引入依赖。
