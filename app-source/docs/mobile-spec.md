# 移动端适配规格（主理人实测基线）

> 目标：让项目在手机上有合格的浏览体验。可参考源站 forum.hanakos.cc 的做法，但**不要求逐像素复刻**。
> 主理人要求：**视觉类决策先给用户看效果对比，不要替用户决定**。

## 一、实测现状（真 Chrome，vite preview 4173，isMobile+hasTouch）

### 1. 横向溢出：全部合格，别改坏

320x568 / 375x667 / 390x844 / 414x896 / 768x1024 / 1440x900 六个视口，所有路由
`document.documentElement.scrollWidth <= innerWidth`，**无横向滚动**。改完必须保持。

### 2. 导航栏：这是唯一明显的缺陷

`.glass-nav` 里 4 个 `.nav-link` 在手机上全挤一行，没有一个会隐藏或折叠：

```
320x568   nav 307x54 left=6    链接 36x28 / 48x28 / 36x28 / 36x28
375x667   nav 360x54 left=8    链接 36x28 / 48x28 / 36x28 / 36x28
390x844   nav 374x54 left=8    链接 36x28 / 48x28 / 36x28 / 36x28
414x896   nav 389x54 left=12   链接 40x28 / 52x28 / 40x28 / 40x28
768x1024  nav 741x62 left=13   链接 62x36 / 77x36 / 62x36 / 62x36
1440x900  nav 1250x62 left=95  链接 62x36 / 77x36 / 62x36 / 62x36
```

- 没有 `navOverflow`（scrollWidth 未超），所以是「挤但没溢出」—— 但 28px 高的点击目标**低于 44px 的可触控最小尺寸**，手机上很难点。
- `.glass-nav` 的 transform 一直是 `matrix(1,0,0,1,-W/2,0)`，即 `translateX(-50%)` 居中。
- 现有断点：只有 640px 和 1024px 两档（影院页 `COLUMN_BREAKPOINTS` 用），导航栏自己**没有任何断点**。

### 3. 源站的做法（实测）

- 375/390/414：header 高 66、`left:16`；文字导航容器 `hidden md:flex`（<768 全部隐藏）；最后只剩**一个 40x40 按钮**，点开是抽屉菜单。
- 768 以上：文字导航回来。
- header：`fixed top-4 left-4 right-4 z-40 max-w-6xl mx-auto transition-transform duration-300 ease-in-out`

### 4. 其他路由（390x844）

| 路由 | 横向溢出 | 备注 |
|---|---|---|
| `/cinema` | 无 | 已响应式降到 4 列；`.neon-marquee-track` 宽 2831px 是跑马灯本体，被父级 overflow 裁掉，**正常** |
| `/music` | 无 | 占位页 |
| `/wall` | 无 | 卡片网格正常；但**导航栏隐藏**，只剩右上角关闭按钮 44x44 |
| `/login` | 无 | 表单正常 |
| `/`（首页） | 无 | — |

## 二、已确认的问题清单

### P1（必须修）导航栏触控目标过小
手机端 `.nav-link` 只有 28px 高，是全站最小的可点区域。

### P2（必须修）导航栏无移动端布局
4 项 + 退出按钮在 320~414 宽度下平铺，字小、间距小。

### P3（建议）缺 `meta viewport` 之外的移动端优化
需要核实 `/wall` 在 `touch-action`、双击缩放、下拉刷新上的行为。

### P4（建议）`/wall` 关闭按钮与安全区
iPhone 刘海/圆角屏需要 `env(safe-area-inset-*)`。

## 三、约束

1. **不能引入横向滚动**（六个视口都要验）。
2. **不能改变桌面端（>=1024px）的任何观感**。桌面截图需要和改动前逐像素对比。
3. 不引入新依赖。项目里**没有测试框架**，别找。
4. `src/assets/main.css` 已有全局 `prefers-reduced-motion` 规则把 `animation-duration` 压到 0.01ms —— 如果新加动画依赖它，必须加放行规则。
5. 不提交 git。

## 四、验收要求

- 六个视口 × 五个路由，全部 `hasHScroll === false`
- `.nav-link` 在手机上可点击高度 >= 44px（或改成抽屉方案）
- 桌面 1440x900 改动前后截图逐像素一致（除非改动本身只在移动端生效）
- 页面错误 0、Vue 警告 0
