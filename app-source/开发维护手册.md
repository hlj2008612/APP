# 开发维护手册

> 这份文档是给「未来的你」看的：半年后回来改代码，照着这里做就不会错。
> 所有命令都在 **`01-源码-puapp`** 目录下执行。

## 一、快速开始

### 环境要求

| 工具 | 版本 | 位置 |
|---|---|---|
| Node.js | v24.12+ | 系统 PATH |
| JDK | 21 | `Z:\AndroidToolchain\jdk21` |
| Android SDK | API 35 | `Z:\AndroidToolchain\android-sdk` |

环境变量通过 `Z:\AndroidToolchain\env.ps1` 加载。如果你换了电脑，
需要自己装一套 JDK 21 + Android SDK，然后改 `打包APK.ps1` 里的 `$ToolchainEnv`。

### 三个最常用的命令

```powershell
cd "D:\桌面\美琴的照片墙APP\01-源码-puapp"

# 1. 本地预览（改了代码想看看效果）
npm run dev

# 2. 打 APK（会自动升级版本号）
.\打包APK.ps1 -VersionName 1.0.4

# 3. 只构建网页版产物（不打包 APK）
node scripts/build-app.mjs
```

## 三、不要做的事

### ❌ 不要运行 `npm install`

**曾经的坑**：`package-lock.json` 曾被一次失败的 `npm install` 写坏，
把 vite 从 8.3.0 降级到 5.4.21，导致 `vite.config.js` 里的 `rolldownOptions`
失效、构建直接失败。

**现在已修复**：lock 文件已用 `--package-lock-only` 重新生成，
和实际安装的版本一致（vite 8.3.0 + rolldown 1.2.9 + plugin-vue 6.0.9）。
理论上 `npm ci` 现在是安全的，但**仍建议不要动依赖**，除非确实要升级。

如果确实需要重装依赖：

```powershell
# 先备份，再试 npm ci（不是 npm install）
Copy-Item package-lock.json package-lock.json.safe
npm ci
# 装完检查这两个版本必须是 8.x 和 6.x
node -p "require('./node_modules/vite/package.json').version"
node -p "require('./node_modules/@vitejs/plugin-vue/package.json').version"
```

### ❌ 不要在中文路径下直接跑 Gradle

AGP 会报 `Your project path contains non-ASCII characters` 并拒绝构建。
`打包APK.ps1` 已经自动处理：先同步到 `Z:\PuAppBuild`（纯 ASCII）再打包。

手工构建时要记住这个规则。

### ❌ PowerShell 脚本必须存成 UTF-8 **带 BOM**

PS 5.1 会把无 BOM 的 UTF-8 当 GBK 解读，中文注释会让解析器报出一堆
莫名其妙的「缺少 }」「字符串缺少终止符」。新建 `.ps1` 时用：

```powershell
[IO.File]::WriteAllText($f, $txt, (New-Object Text.UTF8Encoding($true)))
```

### ❌ 图片绝对路径不能用 `/images/xxx`

原项目用 `import.meta.env.BASE_URL` 拼路径，在 APK 里 `base = './'`，
所有图片必须走后端 API，不能引用包内静态图片。

## 七、排查问题

### 照片显示不出来

1. 在 APP 登录页点 **`? 运行诊断`**
2. 看「图片加载实测」三行结果：
   - `<img> 直连` 成功 → 正常，没有问题
   - **`fetch→blob` 成功但 `<img>` 失败 → Private Network Access 拦截**（1.0.4 已修复，见下）
   - 两个都失败 → 网络不通，检查服务器地址和端口转发
3. 复制报告发出来

#### 【已修复】真机照片空白，模拟器正常（1.0.4）

**现象**：手机安装 APK 后所有照片空白；同一个 APK 在 MuMu 模拟器里完全正常。

**诊断报告特征**（这是决定性判据）：

```
<img> 直连   -> 失败  onerror
fetch→blob  -> 成功  17262 字节  image/webp
```

**根因**：Chromium 的 **Private Network Access** 拦截。
Capacitor 用 `https://localhost` 起页面（安全上下文），而照片服务器是
`http://192.168.x.x:18000`（明文私有网络）。浏览器内核自己发起的子资源请求
（`<img src>`）会被判定为「安全上下文请求不安全的私有网络资源」而直接拦掉，
**连网络包都不会发出**，所以只有 `onerror`，没有 HTTP 状态码。

同一地址用 `fetch()` 却能成功：`fetch` 是显式跨源请求，走 CORS，
后端已经放行，不需要 PNA 预检。这就是诊断页里两种方式结果相反的原因。

**模拟器为什么正常**：MuMu 与宿主机同网段，`192.168.3.26` 被判定为
「本机私有网络」；手机走不同网段，成为「跨私有网络」，拦截规则更严。

**修复方式**：`src/core/imgBridge.js` —— 把所有 `http://` 图片地址先
`fetch` 成 Blob，再转成 `blob:` URL 喂给 `<img>`。`blob:` 与页面同源，
不受 PNA 约束。`https://` 地址照旧直连，不做多余中转。

接入位置：
- `src/views/Pictorial.vue` — `disp(card)` / `dispFull(card)`（4 处 img）
- `src/views/Cinema.vue` — `disp(card)`（1 处 img）
- `src/core/renderer.js` — `setImgSrc()`（照片墙 canvas 用的 Image 对象）

**以后要不要删掉这层中转？** 不用。如果将来后端上了 HTTPS，
`needsBridge()` 会自动对 https 地址返回 false，中转层变成透明直通，
不产生额外开销。留着它，本地 HTTP 调试和正式部署都能用同一份代码。

**注意**：中转会让每张图多一次内存拷贝（Blob 存在 JS 堆里），
所以 `imgBridge.js` 里做了上限 400 张的粗略 LRU 回收。照片量很大时
（几千张同时滚动）要留意内存，必要时把 `MAX_CACHE` 调小。

### 登录报「无法连接服务器」

- 检查手机和电脑是否在同一 WiFi
- 检查 `D:\WinServer2019\软件server\tools\setup-port-forwarding.ps1` 是否跑过（需管理员）
- 电脑上直接访问 `http://192.168.3.26:18000/api/health` 看通不通

### 构建报 `path contains non-ASCII`

你的项目路径含中文。用 `打包APK.ps1`，它已经处理了。

### 构建报找不到 rolldown

vite 被降级了。检查 `node -p "require('./node_modules/vite/package.json').version"`，
如果是 5.x 就说明依赖被 npm install 改坏了，参考第三节恢复。

### APP 白屏

多半是 ProGuard 把 Capacitor 的类删了。检查 `app/proguard-rules.pro`
里的 `-keep` 规则还在不在。

## 八、版本号规范

- `versionCode` 每次发版 +1（自动，`打包APK.ps1 -VersionName` 会处理）
- `versionName` 用 `主.次.修` 三段
- 手机安装新版本要求 `versionCode` 必须比已装的大，否则会提示「未安装」
