# 构建与部署

> ## 🚨 不要跑 `npm install` / `npm ci`
>
> `package.json` 与 `package-lock.json` **不同步**，实际状态如下：
>
> | 包 | package.json 声明 | package-lock.json | 实际安装（node_modules） |
> |---|---|---|---|
> | vue | `^3.4.0` | `^3.5.42` | **3.5.43** |
> | vue-router | `^4.3.0` | `^4.6.4` | **4.6.4** |
> | vite | `^5.0.0` | `^8.3.0` | **8.3.0** |
> | @vitejs/plugin-vue | `^5.0.0` | `^6.0.8` | **6.0.9** |
> | gsap | **无** | `^3.15.0` | **3.15.0**（已不再使用） |
>
> **后果**：
> - `npm ci` 会直接失败（lock 与 package.json 不一致）。
> - `npm install` 会把 vite 降到 **5.x**，并把 gsap 装回来。
>   而 `vite.config.js` 用的是 **Vite 8 的 `build.rolldownOptions`** —— 降级后这段配置
>   整段失效，产物目录、分包、体积报告全变，本文档里 157.27 kB 那套数据随之作废。
>
> **结论**：`node_modules` 已就绪，直接 `npm run build` 即可。
> 若确实需要重装，先把 package.json 的版本对齐到 8.3.0 / 3.5.43 / 6.0.9，
> 并从 lock 里删掉 gsap，否则构建行为会变。

## ⚠️ 本机 emptyOutDir 失效（重要）

本机 Node v24.12.0 上 `fs.rmSync` **静默返回且不删除任何东西**（不抛错、不警告）。
Vite 的 `emptyDir()` 用的正是 `rmSync`，所以 `dist/assets/` 永远清不掉，
每次构建只在里面**新增**带新哈希的产物，旧产物无限累积并被一起上传。

**已在 `vite.config.js` 里用 `removeStaleOutput()` 修掉**：在 `buildStart` 里
用 `fs.promises.rm` 清空 `dist` 顶层（跳过 `.git`）。有环境变量
`PHOTO_WALL_ALLOW_DIST_GIT=1` 可跳过。

实测 `rmSync` 行为：
- `rmSync(非空目录, {recursive:true, force:true})` → 目录仍在 ❌
- `rmSync(普通文件)` → 文件仍在 ❌
- `unlinkSync(文件)` → ✅
- `fs.promises.rm(目录, {recursive:true, force:true})` → ✅

## 部署到 gh-pages

线上源是 `gh-pages` 分支。**实际部署方式是下面的 worktree 流程**：
本地 `npm run build` 后把 `dist/` 同步进 `gh-pages` 的临时 worktree 并 `git push`。

> 历史备注：早期用户确实试过「本地 build 后手动上传 dist/」，但 `origin/gh-pages` 上现在是
> 一串真实的部署提交（`eb43ecb` / `76dfbfd` / `fae935e` …）。
> **不要再用 FTP/网页上传**，那会绕过 commit，让 gh-pages 历史断掉、无法回溯与回滚。

### worktree 部署流程（可复用）

```
1. 构建：npm run build
2. 建临时 worktree：
   git worktree add --detach "<绝对路径>" origin/gh-pages
   ⚠️ 路径必须写死绝对路径。run_code 里整个 process.env 是空的，
      process.env.TEMP 是【undefined】（pwsh 里 $env:TEMP 反而正常），
      用 process.env.TEMP + "\\ghp_..." 会拼成相对路径 "undefined\\ghp_..."，
      git worktree add 不报错、静默建到项目目录内部（曾造成不可删的 undefined\\ 目录事故）
3. 校验：fs.realpathSync(WT) === WT 且 WT/index.html 存在
4. 清空：git rm -r --cached . -q（cwd=WT）→ 删掉除 .git 外所有内容
5. 拷贝：从 dist/ 逐项 fs.cpSync 到 WT（跳过 .build-report.json）
6. 提交：git add -A → git commit -F <绝对路径消息文件>
7. 推送：git push origin HEAD:gh-pages（cwd=WT）
8. 清理：git worktree remove --force <WT> + git worktree prune
```

### 提交信息必须无 BOM

PowerShell here-string 写文件会带 UTF-8 BOM，`git log` 首字符码会变成 65279 而非正常字符。
**一律用 Node `fs.writeFileSync` 写**，提交前校验首字节不是 `0xEF`。

`git commit -F` 用相对路径时必须配 `workdir`，且文件建在项目根；
绝对中文路径会报 `fatal: could not read log file`。
