## 环境陷阱清单

| 陷阱 | 表现 | 解法 |
|---|---|---|
| `process.env.TEMP` 是**空字符串** | 拼出 `undefined\ghp_...` 相对路径，静默建到项目内 | 一律写死绝对路径 |
| Node ESM 导入绝对路径 | `ERR_UNSUPPORTED_ESM_URL_SCHEME` | 脚本放 pw_tools 内用裸模块名 |
| Chrome libpng 噪音 | 大量 `iCCP: known incorrect sRGB profile` | `\| Where-Object { $_ -notmatch 'libpng' }` |
| Node `fetch()` 全失败 | `TypeError: fetch failed` | 用 `curl.exe` |
| `Invoke-WebRequest` | 「非交互模式」报错 | 同上 |
| PowerShell 5.1 不支持 `&&` | 「标记"&&"不是有效语句分隔符」 | 分两次调用 |
| cmd.exe 不支持 `;` | `error: unknown switch ';'` | 用 `&&` 或分两次 |
| run_code 里写含双引号的多行字符串 | TS 词法错误 `Expected ',', got '<lexing error>'` | 改用数组 `.join('\n')` |
| 文件 CRLF vs LF | `String.replace` 匹配不到 | 用 `split(/\r?\n/)` 按行处理 |
| `rmSync` 报 EPERM | Chrome 仍持有文件句柄 | 先 `Stop-Process` 杀进程再删 |
| `fs.rmSync` 静默失效 | 见 03-构建与部署 | 用 `fs.promises.rm` |
| PowerShell 显示中文乱码 | `鍏ㄥ眬閰嶇疆` | 是控制台代码页假象，**文件本身是好的** |
| `Measure-Object -Line` | 把 283 行报成 201 行 | 别用它统计行数，用 read 工具 |
| git 写 stderr 显示红色 | `To https://...` 显示为 RemoteException | 正常回执，不是失败 |
| 写含反引号的 markdown | run_code 的模板字符串里反引号会终止字符串 | 用 `String.fromCharCode(96)` 拼接，或改用普通字符串数组 |
| 反引号内以反斜杠结尾 | 行内代码里反斜杠紧贴结束反引号会被当成转义，markdown 渲染错乱 | 路径末尾不要紧跟反引号，或去掉尾部反斜杠 |

## 校验 UTF-8 是否真的损坏

PowerShell 控制台乱码很容易误判文件损坏。可靠方法：

```js
const buf = fs.readFileSync(p);
// 用 TextDecoder 严格模式解码，抛错才是真损坏
new TextDecoder('utf-8', { fatal: true }).decode(buf);
```

## 移动端实测环境（playwright-core）

- 脚本目录 `C:\Users\黄立键\AppData\Local\Temp\pw_tools`，必须放这里才能用裸模块名 `import { chromium } from 'playwright-core'`。

## Node 改文件的安全做法（2026-10-21 踩坑）

`fs.writeFileSync(path, cond ? a : b)` 这种写法里，若第二个参数被误写成字符串表达式，
会**静默覆盖整个文件**。一次失误把 `NavBar.vue` 从 20593 B 覆盖成 115 B。

**必须遵守**：
1. 改文件前先 `fs.copyFileSync` 备份到项目外（`C:/Users/黄立键/AppData/Local/Temp/`）。
2. 写入前自检：`if (out.length < 原长度 * 0.9) throw` + 关键标记（`<template>` / `</style>`）存在性。
3. 多行替换用**字符串精确替换**（`src.replace(oldBlock, newBlock)`），不要用
   `findIndex` + `splice` —— 锚点没匹配时 `findIndex` 返回 -1，`splice(-1,0,...)` 会插到倒数第一行之前，
   反而让文件变小。两次触发写入自检、两次保住了文件。
4. 中文文件的 `statSync().size` 是**字节数**，`string.length` 是**字符数**，两者不等，
   用前者判断「变小了」会误判。
5. 恢复手段：`git checkout -- <file>`（前提是未提交的改动不想要）。

## 模拟器 / 真机调试（2026-10-24 补测踩坑，逐条实测）

### MuMu 模拟器连 ADB
- ADB 路径：`Z:\AndroidToolchain\android-sdk\platform-tools\adb.exe`
- MuMu 自带 adb 端口被占用时会先看到 `emulator-5554 offline`，**不要用它**；
  正确做法是 `adb connect 127.0.0.1:7555`，连上后设备名就是 `127.0.0.1:7555`。
- 设备是 x86_64、Android 15、物理 `1440x2560`、当前横屏（`SurfaceOrientation: 1`）。

### ⚠️ 点击坐标：用 uiautomator 的 bounds，别用截图坐标
- `adb shell input tap` 用的是**逻辑横屏坐标**（`0..2560 x 0..1440`）。
- 屏幕截图也是 `2560x1440`，看起来一样，但**MuMu 宿主窗口有自己的缩放/偏移**；
  用「看着截图猜坐标」会连续点偏（本次因此把画报 tab 点了十几次都没进）。
- 正确姿势：`adb shell uiautomator dump /sdcard/u.xml` → `adb pull` → 找目标节点 `bounds="[x1,y1][x2,y2]"`，
  取中心 `((x1+x2)/2, (y1+y2)/2)` 再 `input tap`。实测画报 tab 中心约 `(986,168)`。
- 注意 uiautomator 的 bounds 是 **WebView 相对坐标（y 从状态栏下 54 起算）**，
  全局坐标要加上状态栏高度；本机加 54 后与 `input tap` 完全对得上。

### 截图：`screencap` + `pull`
- `adb exec-out screencap -p > x.png` 在 PowerShell 里会把二进制当文本管线处理，**可能得到坏 PNG**
  （本次第一张就报 `Unsupported or malformed image data`）。
- 稳妥做法：`adb shell screencap -p /sdcard/s.png` 然后 `adb pull /sdcard/s.png <ASCII 路径>`。
- **`adb pull` 的目标路径不能含中文**：`D:\桌面\...\07-验证截图\模拟器实测\` 会报
  `cannot create file/directory`。先 pull 到 `C:\Users\<用户>\AppData\Local\Temp\` 再 `Copy-Item` 过去。
